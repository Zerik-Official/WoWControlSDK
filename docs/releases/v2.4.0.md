# WoWControlSDK 2.4.0

WoWControlSDK 2.4.0 lets addons talk to an application without leaving a single global behind: they print to chat, add chat commands, expose functions and save data through the `SDK` object, and the application reads and changes that data even when the addon is not loaded.

Applications can now drive the login screens without touching the game window, answering two-step codes, listing realms and following character creation. Social events tell who is on the other side with the race, gender and class of the player, and the hidden start no longer writes into any import table.

## Highlights

- **Addons without globals** — `SDK.Print` writes to chat, `SDK.RegisterCommand` adds chat commands through the game's command cache without `SLASH_*` names or a `SlashCmdList` entry, and `SDK.Expose` keeps functions for `lua.call` (new `addon` parameter) inside the bridge. The example addon leaves no globals.
- **Saved data** — `SDK.Save`, `SDK.Load`, `SDK.Delete`, `SDK.Keys` and `SDK.OnDataChanged` store an addon's data in `WTF\WoWControlSDK\AddonData\<addon>.json`, written within a quarter of a second. `lua.getStorage` and `lua.setStorage` let the application read and change it.
- **Login codes** — `client.authChallenge` and `client.authChallengeClosed` report the token, PIN and matrix dialogs; `client.submitAuthCode` answers tokens and PINs (mapping the digits to the shuffled keypad) and `client.cancelAuth` cancels the login.
- **Realms** — `client.getRealms` lists name, category, characters, flags, population and state; `client.realmListOpened` and `client.realmListClosed` follow the realm list window.
- **Screens** — `client.screenChanged` reports character creation with code `4` and carries `oldName` and `newName`, so screens without a code such as `realmwizard` are reported too.
- **Player of social events** — friends, whispers, group invitations, summons, trades and duels carry a `player` object with `race`, `gender` and `classId` from the client's name cache, or `null` when the player is not cached yet.
- **Hidden start with Windows hooks** — an in-context `EVENT_OBJECT_CREATE` hook and a `WH_CBT` hook keep the window invisible and without focus until `window.show`, instead of import table hooks.
- **Version** — `dll.getInfo` and the console banner report `2.4.0`.

## Upgrading from 2.3

1. **`client.screenChanged`** — character creation is code `4` instead of `0`; screens without a code keep `0` and are told apart by `newName`.
2. **Addons** — addons that read the example addon's globals (`WoWControlSDKExample`, its SavedVariables or `SLASH_WOWCONTROLSDKEXAMPLE1`) must use `lua.call` with `addon`, `lua.getStorage` and `lua.setStorage` instead.
3. **Social events** — every social payload has a new `player` field; clients that validate payloads strictly must accept it.

## Requirements

- Windows 7 or later for the SDK; Windows 10 or 11 for WoWControl Client.
- World of Warcraft 3.3.5a (32-bit client).
- To run the client from source: Python 3.10 or later with `customtkinter==6.0.0`, `pywin32==312` and `pillow==12.2.0`.

## Verify the download

```powershell
Get-FileHash .\WoWControlSDK.dll -Algorithm SHA256
```

The hash must match `artifacts["WoWControlSDK.dll"].sha256` in `manifest.json`. The commit the DLL was built from can be checked without the game:

```powershell
.\WowInjector.exe --dll .\WoWControlSDK.dll --call dll.getInfo
```
